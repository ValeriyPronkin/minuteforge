# Памятка: как запустить

Одна страница для тех, кто **ставит инструмент себе**. Здесь только порядок
действий; почему всё устроено именно так — в [README](README.md), а как
пользоваться готовым приложением — в [GUIDE](GUIDE.md).

## Что понадобится

* **Видеокарта NVIDIA.** Без неё распознавание работает, но час записи
  считается часами вместо минут.
* **Python 3.10 или новее.**
* **ffmpeg** — им извлекается звук из видео.
* **Аккаунт на huggingface.co** — бесплатный, нужен для моделей диаризации.
* **Ollama или LM Studio** — локальная языковая модель, которая ищет
  поручения.

## 1. Поставить

```bash
git clone https://github.com/ValeriyPronkin/minuteforge
cd minuteforge
python -m venv .venv
.venv\Scripts\activate          # Windows; на macOS и Linux: source .venv/bin/activate

pip install -r requirements.txt        # протокол и интерфейс
pip install -r requirements-asr.txt    # распознавание, только с видеокартой
```

**Внимание, главная ловушка.** Обычная установка torch даёт сборку **без
CUDA**: всё выглядит исправным, но считает процессор, и час записи займёт
несколько часов вместо пяти минут. Поэтому torch ставится отдельно:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

Точную команду под свою видеокарту берите на pytorch.org.

ffmpeg ставится отдельно, он не питоновский:

| Система | Команда |
|---|---|
| Windows | `winget install ffmpeg` |
| macOS | `brew install ffmpeg` |
| Ubuntu | `sudo apt install ffmpeg` |

## 2. Получить токен HuggingFace

**Токен нужен свой.** Он привязан к вашему аккаунту и заменяет пароль:
чужой брать нельзя, а свой — дело двух минут.

Сначала **примите условия двух моделей** — без этого токен бесполезен:

1. `huggingface.co/pyannote/speaker-diarization-3.1`
2. `huggingface.co/pyannote/segmentation-3.0`

На каждой странице, на вкладке **Model card**, сразу под вкладками ищите
строку про доступ:

* **«You need to agree to share your contact information»** с полями и
  кнопкой **Agree and access repository** — заполните и нажмите.
* **«You have been granted access to this model»** — согласие уже дано,
  делать ничего не нужно. Так выглядит страница у тех, кто соглашался
  раньше, и искать там форму бесполезно: её не покажут второй раз.

Чёрная кнопка **Use this model** в правом верхнем углу — это подсказка с
кодом, согласия она **не даёт**.

Доступ у аккаунта и доступ по токену — разные вещи: согласие может быть
дано, а токен создан с урезанными правами, и тогда модель всё равно не
скачается. Проверяются они вместе, кнопкой «Проверить доступ к моделям» в
приложении.

Затем создайте токен на `huggingface.co/settings/tokens` → New token, тип
**Read**. Больше прав не нужно.

И положите его в переменную окружения:

```powershell
# Windows, PowerShell — потом перезапустить терминал
setx HF_TOKEN "hf_..."
```

```bash
# macOS и Linux
echo 'export HF_TOKEN=hf_...' >> ~/.zshrc && source ~/.zshrc
```

В файлы проекта токен вписывать нельзя — ни в настройки, ни тем более в код.

## 3. Поднять языковую модель

```bash
ollama serve
ollama pull mistral
```

Она работает на вашей машине, наружу ничего не уходит.

### Если моделей в свободном доступе нет

На закрытой машине выбор бывает узким: доступен один файл GGUF из
внутреннего хранилища, и всё. Это не помеха — инструменту всё равно, какая
модель отвечает, лишь бы по OpenAI-совместимому протоколу.

**LM Studio** понимает GGUF как есть: откройте файл, запустите сервер и
поставьте в приложении адрес `http://localhost:1234/v1`.

**Ollama** принимает GGUF через файл `Modelfile` рядом с моделью:

```
FROM ./qwen2.5-coder-3b-instruct-q8_0.gguf
```

```powershell
ollama create qwen-coder-3b -f Modelfile
```

После этого она появится в `ollama list` и в списке моделей приложения.

Модель, дообученная на коде, для деловой речи не идеальна и недоберёт
тонких поручений. Но строгий формат ответа — `Поручение / Кому / Срок` —
такие модели держат хорошо, так что начать с неё можно.

## 4. Запустить

```bash
streamlit run app/streamlit_app.py
```

Сначала — одна команда, которая разом скажет, что готово, а что нет:

```bash
minuteforge check
```

Она проверяет ffmpeg, видит ли torch видеокарту, есть ли доступ к моделям
диаризации и отвечает ли локальная модель. Запускать её нужно **до** первого
расчёта: без CUDA всё выглядит исправным и просто считает в двадцать раз
дольше, а понимаешь это через час.

В панели слева те же проверки есть кнопками — **Проверить доступ к моделям**
и **Проверить связь**. Обе занимают секунду и избавляют от главной обиды: когда
отказ вскрывается через сорок минут распознавания.

Дальше три шага:

1. **Загрузите запись** и нажмите «Распознать». Это надолго: час записи —
   минуты на видеокарте.
2. **Скажите, кто есть кто.** Под каждой меткой показана её первая реплика —
   по ней и опознают. Метку, в которой не уверены, оставьте пустой.
3. **Соберите протокол.** Скачайте документ и таблицу поручений.

## Без браузера

То же самое из командной строки — пригодится, когда записей много:

```bash
minuteforge check                    # всё ли настроено
minuteforge recognize meeting.mp4    # стенограмма
minuteforge protocol meeting_segments.json --name SPEAKER_00="Орлов В.П."
```

## Если что-то не пошло

| Что видно | В чём дело |
|---|---|
| «Условия модели не приняты» | подписана одна страница из двух, чаще забывают `segmentation-3.0` |
| «ffmpeg не найден» | не поставлен ffmpeg, см. шаг 1 |
| «Модель не отвечает» | не запущен `ollama serve` |
| В браузере по адресу модели 404 | так и должно быть: это корень API, а не страница. Проверяйте по `http://localhost:11434` — ответит «Ollama is running», и по `/v1/models` — выдаст список моделей |
| Распознавание идёт часами | работа пошла на процессоре: нет видеокарты или не встали драйверы CUDA |
| CUDA out of memory на диаризации | видеопамять занята чем-то ещё: закройте Ollama или задайте `OLLAMA_KEEP_ALIVE=0`, возьмите модель Whisper поменьше |
| Один человек разделился на двух | обычное дело: назначьте обеим меткам одно имя, реплики сольются |

Повторный запуск на той же записи не пересчитывает то, что уже сделано:
шаги сохраняются в `data/work`. Чтобы посчитать заново, удалите оттуда файлы
`transcription.json`, `aligned.json`, `segments.json`.

## Чего инструмент не делает

Протокол, собранный автоматически, — **черновик**. Модель может принять
обсуждение за поручение или упустить сказанное вскользь. У каждого поручения
в таблице есть время и цитата, из которой оно выписано: по ним вычитка идёт
чтением, а не перемоткой записи. Вычитать перед рассылкой обязательно.

## Обновление машины без интернета

На закрытом контуре обновляются через bundle — один файл, в котором лежит
вся история репозитория.

На машине с интернетом:

```bash
git pull
./scripts/transfer.sh          # соберёт ~/minuteforge-transfer/
```

Рядом с бандлом появится `ВЕРСИЯ.txt` — коммит, который в нём лежит. Это не
формальность: файл со старым содержимым и свежей датой выглядит как
обновление, но им не является, и тогда исправления «не появляются», а
причину ищут в приложении.

На закрытой машине, в папке с приложением:

```
git pull D:\перенос\minuteforge.bundle main
```

Первый раз — `git clone D:\перенос\minuteforge.bundle minuteforge`.

**Перезапустите приложение целиком** — Ctrl+C и снова `streamlit run`.
Streamlit перечитывает сценарий при изменениях, но модули, уже загруженные
в память, оставляет прежними: после обновления приложение может работать
старым кодом.

Проверка одна: строка **«Версия в памяти»** в шапке приложения должна
совпасть с `ВЕРСИЯ.txt`. Не совпала — обновление не доехало.

## Если видеокарты нет

Работать будет. Приговор — только для привычки «загрузил двухчасовую запись
и жду»: на процессоре она считается часами.

Три вещи, которые делают инструмент пригодным без CUDA:

* **Модель поменьше.** В своём `config.yaml` (копия `config.example.yaml`)
  поставьте `asr_model: small` вместо
  `medium`. На совещании в помещении с приличным микрофоном разница в
  разборчивости невелика, а времени уходит вдвое меньше. Считается всё в
  int8 — на процессоре это единственный разумный режим, и выбирается он сам.
* **Временной интервал.** Поручения на совещании дают в конце. Двадцать
  минут вместо двух часов — это двадцать минут ожидания вместо нескольких
  часов, и точность протокола от этого только растёт.
* **Отключить диаризацию**, если говорящих различать не нужно (`--no-diarize`
  в командной строке). Разметка по голосам стоит примерно столько же, сколько
  само распознавание.

**Apple Silicon** используется наполовину, и это не недоделка. Само
распознавание идёт через библиотеку, которая графическое ядро Apple не
умеет вовсе, — оно считается на процессоре. А выравнивание и разметка
голосов обычные, torch-овые, и они уходят на графическое ядро сами.
Половина работы ускоряется, ничего настраивать не нужно.

Получасовой фрагмент на `small` — примерно столько же реального времени.
Двухчасовую запись такая машина осилит за ночь, и это нормальный способ ей
пользоваться: поставили вечером, утром забрали стенограмму. На Intel-маках
графического ускорения нет ни на одном шаге — там считает только процессор.

Отдельно про поручения: языковая модель к видеокарте не привязана. Ollama на
Apple Silicon работает на встроенном графическом ядре и модель 7–14B тянет
без затруднений — этот шаг узким местом не будет.
