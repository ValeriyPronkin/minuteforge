# minuteforge

Протокол видеосовещания с поручениями. Распознаёт речь с разделением по
говорящим и извлекает поручения — что поручено, кому, к какому сроку.

**Всё считается на своей машине.** Ни запись, ни стенограмма никуда не
уходят: распознавание идёт локально, языковая модель работает рядом, через
Ollama или LM Studio. Для совещаний с внутренней кухней это условие, при
котором инструментом вообще можно пользоваться.

Внешнюю модель подключить можно — она заметно точнее, — но это осознанный
шаг: тогда стенограмма уходит на чужой сервер, и приложение об этом
предупреждает. Запись не уходит никогда.

## Что получается

```markdown
# Протокол рабочего совещания

**Дата:** 05.06.2025, 11:00
**Участники:** Орлов В.П., Ким С.А., Асанов Т.Р., Лебедева А.И.

## Поручения

| № | Время | Поручение | Исполнитель | Срок |
|---|---|---|---|---|
| 1 | 00:12:40 | Подготовить план работ по выгрузке справочников | Ким С.А. | до пятницы |
| 2 | 00:31:05 | Развернуть демонстрационный стенд | Асанов Т.Р. | к среде |

### Требуют уточнения

Прозвучали, но исполнитель не назван:

- **01:05:30** Собрать справку по инцидентам за квартал
```

Последний раздел — не украшение. На совещании регулярно звучит «надо собрать
справку», а кому — не говорят. Такое поручение нельзя ни выбросить, ни
приписать наугад.

Отметка времени — тоже не украшение. Протокол вычитывают, и без неё сверка
каждого пункта означает поиск места в двухчасовой записи. В таблице
поручений рядом лежит и сама реплика, из которой пункт выписан: обычно
видно сразу, поручение это или пересказ доклада.

Каждый разбор кладётся в свою папку с датой — прошлые прогоны остаются на
месте, иначе не с чем сравнить, когда меняешь модель или настройки.

## Как устроено

| Шаг | Что происходит |
|---|---|
| 1 | Из видео извлекается звук: моно, 16 кГц |
| 2 | WhisperX превращает речь в текст и выравнивает по времени |
| 3 | Диаризация делит запись по говорящим |
| 4 | **Человек** говорит, кто есть кто |
| 5 | Стенограмма режется на фрагменты под окно модели |
| 6 | Модель извлекает поручения из каждого фрагмента |
| 7 | Собирается протокол — по вашей форме, если она задана |

Четвёртый шаг человеческий намеренно: машина различает голоса, но не знает
имён, а подписать чужую фамилию под чужими словами хуже, чем оставить метку.

Подробнее — [docs/algorithm.md](docs/algorithm.md).

## Что нужно

Видеокарта NVIDIA, Python 3.10+, `ffmpeg`, аккаунт HuggingFace для моделей
диаризации и запущенная Ollama или LM Studio.

Без видеокарты работает, но час записи считается часами вместо минут.
Лечится не терпением, а моделью поменьше и временным интервалом на нужный
кусок записи — [как именно](QUICKSTART.md#если-видеокарты-нет). На Apple
Silicon распознавание идёт на процессоре (библиотека счёта графическое ядро
не умеет), а выравнивание и разметка голосов — на графическом ядре.

## Установка

```bash
git clone https://github.com/ValeriyPronkin/minuteforge
cd minuteforge
pip install -r requirements.txt        # протокол и интерфейс
pip install -r requirements-asr.txt    # распознавание, только с видеокартой
```

**Главная ловушка:** обычная команда `pip install torch` ставит сборку **без
CUDA** — всё выглядит исправным, но считает процессор. Torch ставится
отдельно, командой с pytorch.org под вашу версию CUDA.

Токен HuggingFace — только через окружение, никогда в файлах проекта:

```bash
export HF_TOKEN=hf_...      # Windows: setx HF_TOKEN "hf_..."
```

Проверить, что всё готово, — до первого расчёта, а не после:

```bash
minuteforge check
```

Порядок действий по шагам — в [QUICKSTART](QUICKSTART.md).

## Запуск

```bash
streamlit run app/streamlit_app.py    # интерфейс

```

## Настройки

Всё в `config.yaml` рядом с проектом — он есть в репозитории, с объяснением
каждого параметра. Файл необязательный. Любое поле переопределяется
переменной окружения с префиксом `MINUTEFORGE_`.

Секретам там не место: токен читается только из `HF_TOKEN`.

## Из чего состоит

| Модуль | Отвечает за |
|---|---|
| `minuteforge.audio` | звук из видео: моно 16 кГц, выравнивание громкости |
| `minuteforge.transcribe` | WhisperX: распознавание, выравнивание, диаризация |
| `minuteforge.blocks` | склейка реплик, метки говорящих, имена участников |
| `minuteforge.chunking` | нарезка под окно модели, с нахлёстом |
| `minuteforge.llm` | запросы к локальной модели |
| `minuteforge.tasks` | промпты и разбор ответа |
| `minuteforge.protocol` | сборка документа и таблицы поручений |
| `minuteforge.pipeline` | всё перечисленное по порядку |

Тяжёлое вынесено на края: ядро работает без видеокарты, без моделей и без
запущенной LLM, и проверяется тестами целиком.

## Состояние

Версия 0.1.0, проверена на живых записях.

**Качество зависит от модели, и сильно.** На одном фрагменте семимиллиардная
нашла три поручения, трёхмиллиардная — ни одного. Подкруткой настроек это не
лечится.

**Исполнитель не приписывается наугад.** Фамилия принимается, только если
она прозвучала рядом с самим поручением — в этой реплике или соседней.
Иначе пункт уходит в раздел «Требуют уточнения»: пустой адресат заставляет
уточнить перед рассылкой, неверный уходит в рассылку как есть.

**Протокол остаётся черновиком.** Модель может принять констатацию за
поручение: «одобрен лимит» превращается в «подготовить лимит». Поэтому у
каждого пункта есть время и реплика-источник — прочитал, сверил,
вычеркнул. Вычитка обязательна, инструмент её ускоряет, а не отменяет.

**Чего нет:** краткого содержания совещания и повестки.

Вопросы и рассказы о том, что не завелось, — в issues. Особенно вторые:
инструмент писался под одну связку железа, и слепых пятен в нём больше, чем
видно изнутри.

## Как делался проект

Код писался в паре с Claude Code — в истории коммитов это видно, соавторство
проставлено явно.

Человеческое здесь — сама задача и предметные решения: что протокол и
стенограмма разные документы; что поручение без исполнителя нельзя ни
выбросить, ни приписать наугад; что список участников не заменяет числа
говорящих; что форму протокола задаёт организация, а не алгоритм; что записи
не должны покидать машину. Плюс проверка на реальных совещаниях, где и
выяснилось, чего стоят модели разного размера.

Совместное — реализация, тесты, документация.

Сначала был рабочий прототип, сделанный руками и проверенный на настоящих
записях. Эта версия написана заново по уже понятному методу — и оказалась
быстрее на порядок именно потому, что первая была.
