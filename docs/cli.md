# Командная строка

## Из командной строки

Интерфейс удобнее для одной записи. Командная строка — когда записей
десяток, когда всё должно идти по расписанию, или когда браузер на машине
открывать не хочется.

```bash
minuteforge check                      # доступ к моделям и связь с LLM
minuteforge recognize meeting.mp4      # запись -> стенограмма (нужна видеокарта)
minuteforge protocol segments.json \
    --name SPEAKER_00="Орлов В.П." \
    --name SPEAKER_01="Сергей Ким" \
    --date "05.06.2025, 11:00"       # стенограмма -> протокол (видеокарта не нужна)
minuteforge run meeting.mp4            # всё разом
```

Команд четыре, а не одна, по той же причине, по которой в интерфейсе три
шага. `recognize` печатает найденные метки говорящих и подсказывает готовую
строку для следующего шага — наизусть их всё равно никто не помнит.

`check` возвращает ненулевой код, если что-то не настроено: годится для
проверки перед пакетным запуском.

## Куда ложится результат

**По умолчанию — в папку заседания, ту же, откуда взяли запись.** У
`recognize` и `run` это папка записи, у `protocol` — папка стенограммы.
Папка заседания узнаётся сама: по присланному секретарём, по своим
подпапкам (`secretary`, `prep`, `runs`) или по тому, что лежит в папке
заседаний из настройки `meetings_dir`. Как названа папка с присланным,
значения не имеет — «secretary», «Секретарь», «от секретаря».

Раскладка та же, что в интерфейсе, и это главное: прогон ложится своей
папкой в `runs`, а в корень папки заседания попадают два файла — стенограмма
заседания и указатель на последний расчёт.

```
2026-10-01/                        папка заседания
├── Секретарь/                     присланное
├── протокол.pdf                   подписанный — кладёт человек, мы не трогаем
├── стенограмма.txt                стенограмма заседания, одна на заседание
├── стенограмма.json
├── последний-протокол.md          свежий расчёт, перезаписывается каждым прогоном
└── runs/
    └── 2026-10-01_1150_large-v3_запись/
        ├── 2026-10-01_1150_large-v3_стенограмма.txt
        ├── 2026-10-01_1150_large-v3_стенограмма.json
        └── 2026-10-01_1150_qwen3-32b_протокол.md
```

Два файла в корне ведут себя по-разному, и разница в смысле файла.
**Стенограмму заседания не трогаем никогда:** это документ, один на
заседание, от него считаются мерки, и какой из расшифровок им быть, решает
человек — вторая расшифровка бывает хуже первой. **Свежий протокол
перезаписывается каждым прогоном:** это не документ, а указатель на
последний расчёт, и устаревший указатель хуже отсутствующего. Зовётся он
`последний-протокол`, а не `протокол`, потому что `протокол` — это
подписанный, и путать черновик машины с документом нельзя.

Протоколы в материалы секретаря не попадают — ни подписанный, ни наши:
попав туда, протокол уходит моделью в тезисы, то есть в подсказку
распознаванию приходит готовый ответ. Узнаются они по концам имени:
подписанный с «протокол» начинается, наш — им кончается. А «Выписка из
протокола № 5.docx» остаётся материалом: это присланное к совещанию, и
терять его нельзя.

Заседания не видно — результат идёт в `output_dir` из настроек. Так бывает,
когда запись лежит в перевалочной (`input_dir`) или рабочей (`work_dir`)
папке: складывать туда протоколы незачем, оттуда их никто не забирает.

`--out` перебивает всё: сказанное явно важнее угаданного. Промежуточное —
извлечённый звук, сотни мегабайт на часовую запись — в папку результатов не
попадает никогда, ему место в `work_dir`.

Прежде `--out` молча указывал на `data/output`, и стенограмма уходила туда
независимо от того, где лежит запись: папку под заседание заводили заранее,
складывали в неё присланное секретарём, а результат находили в перевалочной
папке приложения и разносили руками.

`run` без `--date` берёт дату совещания из самой записи — из имени файла
(«Совещание 07.09.2026.mp4») или из свойств контейнера — и печатает,
откуда взял. Это не мелочь: от даты совещания считаются сроки, а при
пакетном запуске вписывать её руками некому. Не нашлась — работа не
останавливается, но в поручениях останется сказанное вслух («через две
недели») без календарной даты, и об этом будет сказано. `--date` заданный
руками ничем не перебивается.

`recognize` печатает ход работы по шагам — в терминале это единственный
признак жизни, потому что часовая запись считается десятки минут молча:

```
  [ 65%] Распознаю речь — 812.4 с
  [ 80%] Выравниваю по времени — 96.1 с
  [100%] Разделяю по говорящим — 233.7 с
```

Шкала грубая: доли шагов взяты из наблюдений, а не измеряются. Точнее не
выйдет — WhisperX не сообщает, сколько минут записи он уже прошёл.

Отсюда и то, как это выглядит: **полоска стоит, а потом прыгает**. Она
отмечает границы шагов, а внутри шага двигать её нечем. Самый долгий шаг —
распознавание — идёт одним куском, поэтому она подолгу держится на одном
месте и потом перескакивает сразу на две трети.

Чтобы это не выглядело зависанием, рядом идёт счётчик времени и крутящийся
значок: они видно живут, пока шаг длится. Обещать проценты, которых никто не
считает, было бы честнее только на вид.

Без установки пакета то же самое доступно как `python -m minuteforge`.

## Из кода

```python
from minuteforge.config import Settings
from minuteforge.pipeline import Meeting, process, save

protocol = process(
    "data/input/meeting.mp4",
    Settings(asr_model="medium", speakers=4),
    meeting=Meeting(
        title="Протокол рабочего совещания",
        date="05.06.2025, 11:00",
        names={"SPEAKER_00": "Орлов В.П.", "SPEAKER_01": "Сергей Ким"},
    ),
)
save(protocol, "data/output")
```

Распознавание и сборку протокола можно развести: первое требует видеокарты,
второе — нет. Стенограмма сохраняется в json, и по ней протокол
пересобирается на любой машине, хоть с другими именами участников.

```python
from minuteforge.pipeline import protocol_from_transcript, transcribe_meeting

transcript = transcribe_meeting("meeting.mp4")            # нужна видеокарта
protocol = protocol_from_transcript(transcript)           # достаточно ноутбука
```
