# Трассировка разбора через Langfuse

Записка о разборе показывает воронку: сколько пунктов ушло на каждой стадии и
почему. Чего в ней нет — отдельного запроса и сравнения прогонов между собой.
А сравнивать приходится постоянно: при температуре 0,1 одна и та же запись
даёт разные списки, и разница видна только по запросам.

Это и берёт на себя Langfuse. Прогон — трасса, имя у неё то же, что у папки
прогона. Каждое обращение к модели — наблюдение внутри: стадия, окно, модель,
температура, указание, ответ, время и токены.

Воронку он не заменяет. «Было 238, стало 134, ушло 104, потому что ни просьбы,
ни повелительного наклонения» — знание о предметной области, и журнал пишет
его лучше любой трассировки.

## Где ставить

**Не на машине с видеокартой.** Требование одно: чтобы приложение до сервера
доставало по сети, и чтобы сеть эта была своей. Langfuse — веб-приложение с
базами, к модели он не обращается вовсе и рядом с ней ему делать нечего.

Более того, на машине с видеокартой ему плохо: ClickHouse, Redis и два
контейнера Node отнимают память и диск у того, что считает распознавание.

Место ему на сервере приложений — там, где уже живут postgres и хранилище.
Тогда и зависимостей меньше: две из четырёх уже стоят.

> [!warning] Что при этом надо решить осознанно
> В трассы ложатся куски стенограммы и готовые поручения. Обещание «ничего
> не уходит с машины» после этого звучит иначе: данные заседаний окажутся и
> на сервере трассировки. Внутри своего контура это обычное дело, но решение
> принимается один раз и сознательно — а облачный Langfuse отпадает без
> обсуждения.

## Что он тянет

Четыре зависимости: **Postgres** (оперативные данные), **ClickHouse** (трассы
и оценки), **Redis** (очередь) и **хранилище объектов S3** (сырые события).
Плюс два своих контейнера — веб и воркер.

Если postgres и файловое хранилище у вас уже есть на отдельных машинах, в
докере остаётся поднять ClickHouse, Redis и два контейнера Langfuse.

## Установка

Сборка под этот случай лежит в репозитории: `deploy/langfuse/`. От той, что
в репозитории Langfuse, она отличается двумя вещами — postgres берётся ваш,
уже поднятый, и выключена отправка статистики.

```
cd deploy/langfuse
cp .env.example .env      # и заполнить
docker compose up -d
```

Что заполнять, расписано в самом `.env.example`: адрес вашего postgres,
сетевой адрес будущего интерфейса, ключи к хранилищу и три секрета Langfuse
(делаются командой `openssl rand`, для каждого своя).

Две вещи, на которых спотыкаются:

* **Базу `langfuse` создать заранее.** Схему приложение сделает само, а базу
  нет: `createdb -h сервер -U postgres langfuse`.
* **`LANGFUSE_URL` — сетевой адрес, а не localhost.** По localhost интерфейс
  откроется только на самом сервере, а переходы после входа сломаются.

Хранилище объектов по умолчанию своё, minio из того же compose-файла. Если у
вас есть своё, S3-совместимое, — укажите его адрес и ключи в `.env`, а службу
minio из compose-файла уберите. Проверить, годится ли ваше: нужен именно S3 —
с ключом доступа и секретом, — а не сетевая папка с доменными правами.

Интерфейс поднимется на `:3000`. Первым делом он попросит завести учётную
запись, организацию и проект.

## Как включить в приложении

В проекте Langfuse: **Settings → API Keys → Create** — оттуда берутся два
ключа.

Ключи задаются переменными окружения, а не файлом настроек: настройки правят,
показывают и пересылают, а секрет показывать нельзя. На Windows — в свойствах
системы или командой `setx`, после чего приложение нужно перезапустить:

```
setx LANGFUSE_PUBLIC_KEY pk-lf-...
setx LANGFUSE_SECRET_KEY sk-lf-...
```

В `config.yaml`:

```yaml
langfuse_enabled: true
langfuse_host: "http://сервер-приложений:3000"
```

И поставить сам пакет — он не входит в обязательные зависимости:

```
pip install langfuse
```

## Проверка

Не на заседании. Возьмите пятиминутный отрезок записи —
`meeting_from_min`/`meeting_to_min`, — соберите протокол и откройте Langfuse.
Там должна появиться одна трасса с именем прогона, а в ней — десяток
наблюдений: «выписка», «отмеченное», «проверка «поручение или доклад»»,
«формулировка по окну».

Полтора часа записи — это больше трёхсот запросов за прогон. Для Langfuse
это пустяк, а вот читать трассу удобнее, начав с короткой.

## Если не поднялось

Разбор идёт дальше и не падает — это заложено. В журнале при этом будет одна
из строк:

* `Трассировка включена, но ключей нет` — не заданы переменные окружения или
  приложение запущено до `setx`;
* `Трассировка не поднялась, иду без неё` — нет пакета `langfuse` или адрес
  не отвечает;
* ничего — значит `langfuse_enabled: false`.

Повторно за прогон попытка не делается: запросов триста, и столько же
одинаковых предупреждений в журнале читать невозможно.
